# 근거 — 왜 이 구조인가

규칙 자체는 [invariants.md](./invariants.md)와 [protocol.md](./protocol.md)에 있다.
여기에는 **그 규칙이 무엇을 겪고 생겼는지**만 둔다. 실행·판정 기록은
`docs/test-reports/`가 소유한다 — 이 문서는 그 보고서를 가리키는 요약이다.

## v1 → v2

| v1(ApcH 안에서) | v2(Stagekeeper) | 왜 |
| --- | --- | --- |
| 상태가 저장소의 md 두 개(`PROJECT_BOARD.md`·`TASK_BACKLOG.md`) | 서비스 DB | 여러 저장소를 하나의 하니스가 관리하고, 게이트를 웹에서 누른다 |
| 게이트를 프롬프트 문구로 막음 | 에이전트 토큰용 MCP 서버에 도구가 없음 | 문구는 어길 수 있지만 없는 도구는 부를 수 없다 |
| 명령 채널 = GitHub 이슈 | `Command` 테이블(Phase 3) | 이슈·PAT·루프 방지 접두가 은퇴한다 |
| 에이전트 정의를 손으로 씀 | `harness.json` → 템플릿 렌더 | 프로젝트마다 roster·검증 명령이 다르다 |

## 골든 diff — 통일 dev 템플릿이 원본과 어디서 갈라지나

`examples/apch/harness.json`의 세 워크스페이스로 `plugin/templates/ko/agents/dev.md`를 렌더해
ApcH 원본 `.claude/agents/{web,admin,backend}-dev.md`와 대조했다(2026-08-29 실측).

| | 줄 | `##` 절 |
| --- | --- | --- |
| 원본 `web-dev.md` | 187 | 9 |
| 원본 `admin-dev.md` | 211 | 10 |
| 원본 `backend-dev.md` | 232 | 10 |
| 렌더 `web-dev` | 194 | 9 |
| 렌더 `admin-dev` | 195 | 9 |
| 렌더 `backend-dev` | 195 | 9 |

렌더 결과의 절 목록은 `web-dev` 원본과 **정확히 같다** — 그것이 공통 골격이다.

### 잔차 네 부류 (의도한 것)

1. **유래 이동** — ApcH 고유의 실증 산문(FEAT-02 사례, 크레딧 로직, Neon/Prisma 명령 이름)은
   템플릿에서 빼고 규칙만 남겼다. 사례는 이 문서가 받는다.
2. **knowledge 이동** — `apps/web/CLAUDE.md` 같은 고정 경로가 `{{ws.knowledge}}`로 바뀌었다.
   워크스페이스에 지식 문서가 없으면 `vars.mjs`가 "없음 — …계획서에 그 사실을 적는다"를 넣는다.
3. **변수 형식** — 담당 표는 `{{roster_table}}`, 검증 명령은 `{{ws.verify_block}}`,
   읽기 전용·범위 밖 목록은 `{{ws.read_only_list}}`·`{{ws.out_of_scope_list}}`로 생성된다.
4. **수단 치환** — 보드·백로그 파일 읽기·쓰기가 전부 `mcp__harness__*` 호출이 됐고,
   `B-7`(백로그에서 항목 제거)은 서버가 하므로 절차에서 사라졌다. `tools:`에 MCP 도구 5개가 붙었다.

### 다섯째 부류가 아니라 알려진 예외

통일 템플릿은 원본 두 개의 절 하나씩을 **떨어뜨린다.**

| 파일 | 잃는 것 | 성격 |
| --- | --- | --- |
| `admin-dev.md` | `## UI 작업이면 frontend-design 스킬을 로드한다` + `tools:`의 `Skill` | 절차 규칙. 절과 도구가 한 몸이다 |
| `backend-dev.md` | `## 순수 모듈 규칙 — 이 에이전트의 핵심 제약` | 검증 게이트의 전제(판단 로직을 stdlib만 쓰는 모듈로 분리) |

**Phase 1은 떨어뜨린 채 간다.** 스모크 저장소는 워크스페이스가 하나라 잃을 절이 없고,
dev의 도구 목록은 스펙 §9가 정한 그대로 지킨다(도구 추가는 권한 확대라 임의로 하지 않는다).
되살리는 방법 — `harness.json`에 워크스페이스별 절 필드를 두거나, 워크스페이스별 오버레이 파일을
두거나, `ws.knowledge`로 옮기거나 — 셋 다 스키마나 생성기 계약을 건드리므로 **Phase 2 제안서가 답한다.**

### 나머지 템플릿의 잔차

- `feature-scout.md` — ApcH의 「자기만의」 렌즈 절을 뺐다. 그건 ApcH 제품(영상 생성)에 고유한
  질문이고, 일반 템플릿의 정찰 질문은 `{{scout.question}}`이 정한다. 제품별 렌즈가 필요하면
  그 질문에 담는다.
- `CLAUDE.runbook.md` — 원본 9단계 중 **8단계(배포 확인 원장 등재)를 통째로 뺐다.**
  `docs/release-checks.md`도 `release-verify` 루틴도 Phase 3다. 남은 단계를 다시 매겨 **8단계**가 됐다.
  7단계의 「범위 밖 의존」 후속 등재는 "웹 백로그에 사용자가 등재한다"로 바뀌었다 —
  백로그 편집이 웹 전용이라 에이전트도 메인 루프도 쓸 수 없기 때문이다.
- 인수 다섯 조건은 원본에서 보드 안내 블록에만 있었다. v2에서는 이 저장소의
  [protocol.md](./protocol.md)가 정본이고, 사용자 저장소에는 런북 7단계가 **본문으로** 싣는다
  — 생성기가 `protocol.md`를 사용자 저장소에 물질화하지 않으므로 참조만 두면 끊긴다.
